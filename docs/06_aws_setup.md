## 概要（旧構成）

ポートフォリオサイトをAWSでホスティングするための環境構築手順。

### 構成図

```
ユーザー
   │
   ▼
CloudFront（CDN + SSL）
   │
   ▼
S3（静的ファイル）

Route 53（DNS）→ CloudFront
ACM（SSL証明書）→ CloudFront
```

### 作業順序

| 順序 | 作業 | 理由 |
|------|------|------|
| 1 | Route 53 ドメイン購入 | DNS設定の基盤 |
| 2 | ACM 証明書リクエスト | 検証に時間がかかる |
| 3 | S3 バケット作成 | コンテンツ配置先 |
| 4 | CloudFront ディストリビューション | CDN + SSL設定 |
| 5 | Route 53 DNS設定 | ドメイン紐付け |

## Step 1: Route 53 ドメイン購入

### 1-1. Route 53 コンソールを開く

1. AWS マネジメントコンソールにログイン
2. サービス検索で「Route 53」を検索
3. Route 53 ダッシュボードを開く

### 1-2. ドメイン登録

1. 左メニュー「登録済みドメイン」をクリック
2. 「ドメインの登録」ボタンをクリック
3. ドメイン名を入力: `amano-amane.com`
4. 「チェック」をクリックして利用可能か確認
5. 利用可能なら「カートに入れる」→「続行」

### 1-3. 連絡先情報入力

1. 登録者の連絡先情報を入力
   - 名前（匿名運営でも本名が必要）
   - 住所
   - メールアドレス
   - 電話番号
2. **プライバシー保護を有効化**（WHOIS に個人情報が公開されない）
3. 「続行」をクリック

### 1-4. 確認と購入

1. 内容を確認
2. 利用規約に同意
3. 「注文を完了」をクリック

### 1-5. 確認メール

- 登録メールアドレスに確認メールが届く
- **必ずリンクをクリックして確認**（しないとドメインが停止される）

### 所要時間

- 通常: 数分〜数時間
- 最大: 3日

---

## Step 2: ACM 証明書リクエスト

> **重要**: CloudFront で使用する証明書は **us-east-1（バージニア北部）** で作成する必要がある

### 2-1. リージョン切り替え

1. 右上のリージョン選択で「米国東部（バージニア北部）us-east-1」を選択

### 2-2. ACM コンソールを開く

1. サービス検索で「Certificate Manager」を検索
2. ACM ダッシュボードを開く

### 2-3. 証明書リクエスト

1. 「証明書をリクエスト」をクリック
2. 「パブリック証明書をリクエスト」を選択 → 「次へ」

### 2-4. ドメイン名追加

1. 完全修飾ドメイン名に以下を入力:
   - `amano-amane.com`
   - `*.amano-amane.com`（ワイルドカード）
2. 「この証明書に別の名前を追加」で2つ目を追加

### 2-5. 検証方法選択

1. **DNS 検証** を選択（推奨）
2. 「リクエスト」をクリック

### 2-6. DNS 検証レコード追加

1. 証明書一覧から作成した証明書をクリック
2. 「ドメイン」セクションで「Route 53 でレコードを作成」をクリック
3. 確認画面で「レコードを作成」をクリック

### 2-7. 検証完了待ち

- ステータスが「発行済み」になるまで待つ
- 通常: 数分〜30分
- 最大: 数時間

---

## Step 3: S3 バケット作成

### 3-1. リージョン切り替え

1. 右上のリージョンを「アジアパシフィック（東京）ap-northeast-1」に戻す

### 3-2. S3 コンソールを開く

1. サービス検索で「S3」を検索
2. S3 ダッシュボードを開く

### 3-3. バケット作成

1. 「バケットを作成」をクリック
2. 設定:

| 項目 | 値 |
|------|-----|
| バケット名 | `amano-amane.com` |
| リージョン | アジアパシフィック（東京） |
| オブジェクト所有者 | ACL 無効 |
| パブリックアクセス | **すべてブロック**（後でCloudFront経由に設定） |
| バージョニング | 無効 |
| 暗号化 | SSE-S3（デフォルト） |

3. 「バケットを作成」をクリック

### 3-4. 静的ウェブホスティング設定（オプション）

> CloudFront経由でアクセスする場合、この設定は不要だが、設定しておくとデバッグに便利

1. バケットを選択 →「プロパティ」タブ
2. 「静的ウェブサイトホスティング」→「編集」
3. 設定:
   - 静的ウェブサイトホスティング: 有効
   - インデックスドキュメント: `index.html`
   - エラードキュメント: `index.html`（SPA用）
4. 「変更の保存」

---

## Step 4: CloudFront ディストリビューション

### 4-1. CloudFront コンソールを開く

1. サービス検索で「CloudFront」を検索
2. CloudFront ダッシュボードを開く

### 4-2. ディストリビューション作成

1. 「ディストリビューションを作成」をクリック

### 4-3. オリジン設定

| 項目 | 値 |
|------|-----|
| オリジンドメイン | S3バケットを選択（`amano-amane.com.s3.ap-northeast-1.amazonaws.com`） |
| オリジンパス | 空欄 |
| 名前 | 自動入力のまま |
| オリジンアクセス | **Origin Access Control (OAC)** を選択 |

1. 「コントロール設定を作成」をクリック
2. デフォルト設定で「作成」

### 4-4. デフォルトキャッシュビヘイビア設定

| 項目 | 値 |
|------|-----|
| ビューワープロトコルポリシー | **Redirect HTTP to HTTPS** |
| 許可された HTTP メソッド | GET, HEAD |
| キャッシュキーとオリジンリクエスト | CachingOptimized（推奨） |

### 4-5. 設定

| 項目 | 値 |
|------|-----|
| 価格クラス | 北米と欧州のみ使用（コスト削減） |
| 代替ドメイン名 (CNAME) | `amano-amane.com`, `www.amano-amane.com` |
| カスタム SSL 証明書 | Step 2 で作成した証明書を選択 |
| デフォルトルートオブジェクト | `index.html` |
| 標準ログ記録 | オフ（コスト削減） |

### 4-6. 作成

1. 「ディストリビューションを作成」をクリック
2. **バケットポリシー更新の警告が表示される**
3. 「ポリシーをコピー」をクリック

### 4-7. S3 バケットポリシー設定

1. S3 コンソールでバケットを開く
2. 「アクセス許可」タブ →「バケットポリシー」→「編集」
3. コピーしたポリシーを貼り付け
4. 「変更の保存」

### 4-8. カスタムエラーレスポンス設定（SPA用）

1. CloudFront ディストリビューション →「エラーページ」タブ
2. 「カスタムエラーレスポンスを作成」

| 項目 | 値 |
|------|-----|
| HTTP エラーコード | 403 |
| エラーレスポンスをカスタマイズ | はい |
| レスポンスページのパス | `/index.html` |
| HTTP レスポンスコード | 200 |

3. 同様に 404 エラーも設定

### 所要時間

- ディストリビューションのデプロイ: 約5〜15分

---

## Step 5: Route 53 DNS 設定

### 5-1. Route 53 コンソールを開く

1. サービス検索で「Route 53」を検索
2. 「ホストゾーン」をクリック
3. `amano-amane.com` のホストゾーンを選択

### 5-2. A レコード作成（ルートドメイン）

1. 「レコードを作成」をクリック
2. 設定:

| 項目 | 値 |
|------|-----|
| レコード名 | 空欄（ルートドメイン） |
| レコードタイプ | A |
| エイリアス | **はい** |
| トラフィックのルーティング先 | CloudFront ディストリビューション |
| ディストリビューション | 作成したものを選択 |

3. 「レコードを作成」

---

## Step 6: 動作確認

### 6-1. CloudFront 経由でアクセス

1. CloudFront のドメイン名（`xxx.cloudfront.net`）にアクセス
2. 正常に表示されることを確認

### 6-2. カスタムドメインでアクセス

1. `https://amano-amane.com` にアクセス
2. 正常に表示されることを確認

### 6-3. HTTPS リダイレクト確認

1. `http://amano-amane.com` にアクセス
2. 自動的に `https://` にリダイレクトされることを確認

## デプロイ手順

### IAM Identity Center 設定（初回のみ）

1. AWS コンソール → IAM Identity Center
2. 左メニュー「許可セット」→「許可セットを作成」
3. 「カスタム許可セット」を選択 →「次へ」
4. 許可セット名: `PortfolioDeployAccess`
5. 「インラインポリシー」に以下を貼り付け:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "S3DeployAccess",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:PutObjectAcl",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::amano-amane.com",
        "arn:aws:s3:::amano-amane.com/*"
      ]
    },
    {
      "Sid": "CloudFrontInvalidation",
      "Effect": "Allow",
      "Action": [
        "cloudfront:CreateInvalidation",
        "cloudfront:GetInvalidation",
        "cloudfront:ListInvalidations"
      ],
      "Resource": "*"
    }
  ]
}
```

6. 「次へ」→「作成」
7. 左メニュー「AWSアカウント」→ 対象アカウントを選択
8. 「ユーザーまたはグループを割り当て」
9. 自分のユーザーを選択 →「次へ」
10. 作成した `PortfolioDeployAccess` を選択 →「送信」

### AWS CLI ログイン

```bash
# ログイン（ブラウザが開く）
aws login
```

### デプロイコマンド

```bash
# ビルド
cd frontend
npm run build

# S3 にアップロード
aws s3 sync dist/ s3://amano-amane.com --delete

# CloudFront キャッシュ無効化（必要時）
aws cloudfront create-invalidation --distribution-id [DISTRIBUTION_ID] --paths "/*"
```

## トラブルシューティング

### 証明書が「検証保留中」のまま

- DNS レコードが正しく設定されているか確認
- 時間を置いて再確認（最大数時間かかる場合あり）

### CloudFront で 403 エラー

- S3 バケットポリシーが正しく設定されているか確認
- OAC が正しく設定されているか確認

### ドメインにアクセスできない

- DNS の伝播に時間がかかっている可能性（最大48時間）
- `nslookup amano-amane.com` で確認
